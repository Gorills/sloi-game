## Реализованный HTTP

| Endpoint | Результат |
|---|---|
| `GET /health` | `{"status":"ok","surface":"design-catalog"}` |
| `GET /` | Собранный HTML; 503 с объяснением, если сборки нет |

Это полный текущий API. Игрового WebSocket, login и inventory endpoint пока нет.

## Предложение для S1 — не готовая схема

Перед реализацией зафиксировать форматы с примерами валидных и невалидных сообщений.
Команда должна различать версию протокола, имя действия, уникальный ID и payload.
Идентичность берётся из серверной сессии, не из произвольного `player_id` в payload.
Результат ссылается на ID команды; snapshot содержит монотонную ревизию мира.
Известные причины отказа — стабильные машинные коды; текст для игрока локализует клиент.

Обязательные решения:

| Вопрос | Инвариант / что уточнить |
|---|---|
| Сессия | Создание/возврат/истечение, вторая вкладка, отзыв токена; не хранить секрет в URL |
| Дубли | Один `(actor, command_id)` → не более одного изменения и воспроизводимый результат |
| Reconnect | Не переигрывать автоматически устаревшие движения/атаки; сначала актуальный snapshot |
| Порядок | Старый snapshot не откатывает presentation-state; полный resync при разрыве истории |
| Валидация | Неизвестные действия/поля, oversized payload, NaN/Infinity, отрицательные величины |
| Потоки | Ограниченные входная частота и очередь; медленный игрок не тормозит общий мир |
| Origin | Явный allowlist; авторизация/проверка прав всё равно обязательны |
| Persistence | Версия схемы, миграция, rollback; результат успеха после commit |

Embedded-профиль будущего игрового сервера: отдельный выключенный по умолчанию флаг,
loopback bind и проверка peer; `Origin: null` не считать аутентификацией и не разрешать публично.
`X-Forwarded-For` от недоверенного клиента не даёт права на embedded-доступ.

## Клиентские интерфейсы

Input → ActionIntent; Transport → validated message; Presentation → read-only view;
Renderer рисует view, DOM UI отображает команды/статусы. Конкретные имена типов
появятся в коде S1, не нужно заранее генерировать пустые интерфейсы.

Любое изменение контракта включает обновление обеих сторон и проверку старого/нового
сообщения по выбранной стратегии совместимости. Основа: [OWASP/FastAPI/SQLite](research.md).
