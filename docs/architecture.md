Status: accepted

## Границы будущей игры

```text
input → client commands → WebSocket adapter → validated command
                                           → domain rules → transaction → result
renderer + DOM UI ← presentation state ← snapshots / acknowledged results
```

Клиент не определяет урон, дроп, валюту, право перехода и результаты транзакций.
Визуальная интерполяция допустима; серверная симуляция не зависит от FPS браузера.

По мере появления поведения выделять `server/domain/` (правила без FastAPI/SQLite),
`server/transport/` (валидация/сессии/доставка), `server/storage/` (транзакции/миграции).
Это будущие границы, не требование заранее создать пустую иерархию.
На клиенте аналогично разделять ввод, транспорт, presentation-state, отрисовку и DOM UI.
Отрисовщик не открывает WebSocket, обработчик клавиши не изменяет authoritative state.

Один процесс Uvicorn, один владелец состояния, одна SQLite на локальном диске.
Не запускать несколько workers с отдельными копиями мира. ORM, Redis, event bus,
ECS и микросервисы не требуются для S1; добавление обосновывается измеренной проблемой.

## Время, конкуренция, ошибки

Сервер использует монотонное время для интервалов. При дискретной симуляции — ограниченное
число догоняющих шагов; не компенсировать минуту простоя внезапным шквалом атак.
Клиент не присылает доверенное время/скорость. Медленный клиент не блокирует остальных:
выходная очередь ограничена, устаревшие snapshots заменяются, критические результаты не теряются молча.

Состояние памяти и SQLite должны совпадать после успешного действия. Подготовить новое
состояние, выполнить транзакцию, затем опубликовать; при ошибке сохранить прежнее.
ACK об успешной награде/покупке — только после commit. После сбоя доставки клиент
получает подтверждённое состояние при reconnect; повтор не выдаёт награду второй раз.

Переход карты атомарно меняет принадлежность: персонаж не существует в двух комнатах.
Скрытую от игрока информацию не отправлять в клиент ради удобства рисования/тестов.

Подробности выбора: [ADR](decisions/0001-foundation.md). Рекомендации основаны на
[FastAPI, SQLite и OWASP](research.md), конкретное разбиение — локальное решение проекта.
