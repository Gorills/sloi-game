# Тестирование и критерий готовности

Status: accepted

## Сейчас и после S1

Foundation проверяет инструменты, документацию, HTTP и каталог UI.
`tests/scene/` проверяет локальный художественный этюд с ходьбой, взаимодействием и
выстрелом по манекену. Сетевых игровых E2E в репозитории ещё нет.
`make check` зелёный не означает, что боёвка или сохранения уже работают.

| Изменение | Обязательная проверка |
|---|---|
| Документ/навык | Ссылки, статус, frontmatter, границы навыка; сверка источника человеком/агентом |
| Игровое правило | Unit: норма, границы, отказ; регрессия воспроизводит исходный дефект |
| Сеть/контракт | Реальное соединение: невалидные данные, дубль, порядок, reconnect, лимиты |
| Имущество/SQLite | Конкурирующие клиенты, повтор ID, rollback, новый процесс после crash |
| UI/ввод/Canvas | Реальный браузер, клавиатура и мышь, фокус, resize/DPR; [визуальная самооценка](design/visual-acceptance.md) для изменённого визуала |
| Новый игровой цикл | Два независимых браузера, настоящий сервер/БД, действия через UI |
| Производительность | Заданный сценарий/устройство, p95 времени кадра/тика и память; не средний FPS |

## Обязательные будущие игровые сценарии

S1: два входа, движение, границы/скорость, неверная команда, отключение,
новая страница, перезапуск процесса и новое действие после reconnect.

Экономика: одновременная заявка на один объект, повтор доставки/покупки,
недостаток ресурса, чужой объект, crash между commit и ACK; без отрицательных балансов.

Экспедиция: подготовка → дорога/Разлом → совместное действие → добыча → возврат;
отдельно поражение, восстановление и вклад в поселение. Помощь не должна ухудшать награду группы.

В unit разрешены подставные часы/RNG. В игровом E2E нельзя телепортировать тестом,
редактировать HP/БД для прохождения, подменять WebSocket или отключать авторизацию.
Read-only диагностика не раскрывает скрытые серверные данные и не заменяет экран.

## Как избегать ложного успеха

Проверять пользовательский результат, а не только вызов функции/наличие кнопки.
Ждать наблюдаемое состояние с deadline, не произвольный sleep; временные интервалы
боевых действий являются частью сценария и должны быть явно обоснованы.
Отдельная SQLite и сервер на тест; fixtures закрывают браузеры, процессы и соединения даже при ошибке.
Собирать pageerror, серверные ошибки, trace и скриншоты до закрытия контекста.
В логах не сохранять session/resume-токены и приватные payload.

Не использовать `skip`, `xfail`, `.only` или `continue-on-error` для обязательной приёмки.
Ошибку окружения отражать как непройденную проверку. Не повышать порог визуального diff,
не обновлять baseline и не ослаблять assertion без объяснения ожидаемого изменения.

Для критической регрессии проверить чувствительность: прежняя версия или локальный
мутант должны провалить тест. Изолированная порча не попадает в основной diff.
Coverage полезен для поиска пробелов; процент не доказывает корректность и не цель сам по себе.

## Свидетельства

Команда, commit SHA, профиль `url|embedded`, версии, результат/число пропусков,
сценарии, артефакты, просмотренные кадры, границы проверки. На финальном SHA нельзя
ссылаться как на проверенный, если после прогона менялись исходники.
Основы подхода: [Playwright](research.md). Human playtest: [методика](design/playtesting.md).
