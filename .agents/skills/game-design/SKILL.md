# Проектирование игрового поведения

## Вход

Прочитай AGENTS.md, docs/product.md, docs/world.md и нужную страницу дизайна.
Уточни по источникам, что факт текста, что мнение персонажа, что гипотеза адаптации.

## Процедура

1. Определи один выбор игрока, его цену и обратную связь; используй шаблон системы.
2. Проверь существенное правило по нужной книге/главе. Нет фрагмента — NOT VERIFIED,
   а не новое правило мира по аналогии с другой RPG.
3. Для референса запиши поддерживаемый принцип и то, что нельзя переносить:
   например, совместные награды не требуют дублировать уникальный предмет.
4. Опиши кооперацию, одиночную подготовку, проигрыш и возвращение; не проектируй
   обязательный онлайн всей группы для каждого действия.
5. Укажи UI/управление/доступность и критерий плейтеста. Раздели functional correctness
   и удовольствие от игры. Цены/тайминги помечай как значения для эксперимента.
6. Сохрани draft до решения владельца; согласованный дизайн не равен реализации.

## Границы

Не сужай мир до первой главы/Колыбели. Не превращай исключения Гриса в стартовые
возможности всех персонажей. Не копируй весь feature set референса.
Не обещай тренды 2027, монетизацию и retention без данных.
Постоянная смерть, PvP и управление городом не вводятся незаметно как техническая деталь.

## Результат

Короткая карточка: основание, предложение, открытые решения, тесты и четыре секции отчёта.
Источники: [G1–G5] и частные рукописи через реестр world; содержание навыка —
проектная процедура, не результат собственного плейтеста референсов.
