# Проверка реальной игры

## Вход

Прочитай AGENTS.md, docs/testing.md, docs/development.md и текущие тесты.
Назови поведение, build SHA, проверяемый инвариант и профиль bootstrap.

## Процедура

1. Для дефекта сначала зафиксируй провал прежнего кода. Проверь, что assertion
   наблюдает пользовательский результат, а не только вызов/наличие элемента.
2. Запусти реальный сервер с отдельной файловой БД. Для multiplayer — минимум
   два изолированных браузерных контекста; укажи, сколько процессов запущено.
3. По умолчанию используй URL. Embedded выбирается явно до прогона и не считается
   проверкой origin/CSP/cookies. Не изменяй browser policies при сетевой ошибке.
4. Проходи через клавиатуру/мышь/формы. Нельзя писать координаты/HP в state,
   подменять WebSocket и ответы или пользоваться служебным teleport.
5. Дожидайся наблюдаемого результата с deadline. Собери pageerror, trace,
   screenshots и безопасные серверные логи; не записывай секретные токены.
6. По риску проверь конкуренцию, повтор, offline/reconnect, новый процесс сервера
   и новое действие после восстановления — одного факта успешного reconnect недостаточно.
7. Просмотри кадры и итоговый diff; запусти затронутые проверки после последних изменений.

## Отказы

Нет браузера/нет сервера/таймаут/skip/xfail — не PASS. Не понижай качество assertions
и не меняй bootstrap автоматически ради зелёного результата.
Unit-clock/mock допустим для правил, но явно отделён от реального E2E.
Не заявляй «интересно играть» на основании автотеста.

## Результат

Команды, SHA, профиль, наблюдения, ошибки, пропуски, артефакты и пределы покрытия.
В foundation тестируется только каталог; игровые E2E появятся с игровой реализацией.
Источники: [S4]; реальные сценарии и запрет тестовых читов — контракт проекта.
