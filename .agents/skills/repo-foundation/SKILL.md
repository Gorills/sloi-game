# Изменение основы репозитория

## Вход

Прочитай AGENTS.md, docs/status.md, docs/governance.md и реальный workflow.
Определи одно новое проверяемое ограничение или один дефект навигации.

## Процедура

1. Найди единственный источник правила; не создавай дублирующую политику.
2. Сверь используемый механизм с официальным источником [S1–S3/S9–S11].
3. Для автоматического gate добавь положительный и отрицательный пример.
4. Проверь, что gate охватывает реальные исходники, а generated/vendor исключаются
   по конкретной границе, не через маску, куда можно незаметно спрятать обычный код.
5. Запусти make check; для workflow сверь фактический результат последнего SHA в GitHub.
6. Обнови индекс/статус. Наличие ruleset JSON не означает его активацию.

## Ошибки

Не ослабляй проверки ради собственной фичи. Не требуй self-approval единственного
владельца. Не добавляй зависимость, которая не используется ни одной проверкой.
Изменение форматирования не доказывает архитектурное улучшение.

## Результат

Одно изменение, проверенные gates, отрицательный пример, фактический статус защиты,
VERIFIED / NOT VERIFIED / ASSUMPTIONS / BLOCKERS. Остановись.
