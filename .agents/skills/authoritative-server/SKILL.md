# Авторитетный сервер

## Вход

Прочитай AGENTS.md, docs/architecture.md, docs/interfaces.md и затронутый код обеих сторон.
Пока есть только HTTP-каталог, не выдумывай готовые игровые endpoints.

## Процедура

1. Запиши инвариант и фактическую последовательность: намерение → проверка →
   транзакция → память → ACK/snapshot. Найди владельца состояния.
2. На границе валидируй тип, диапазон, размер, действие, сессию и права. Origin
   не заменяет авторизацию. Не доверяй client clock, координатам и балансу.
3. Для награды/покупки обеспечь атомарность и защиту от повторного command ID;
   один уникальный груз не дублируется даже при двух независимых запросах.
4. Проверь ошибку commit и crash до ACK: клиент может узнать подтверждённый результат
   после reconnect, память не остаётся с несохранённой успешной операцией.
5. Обработай disconnect/cancellation и медленного получателя; очереди ограничены.
   Не держи транзакцию или общий lock во время сетевого await.
6. Добавь unit + integration; для изменения пользовательского сетевого поведения
   используй game-verification. Запусти проверки на свежей файловой SQLite.

## Границы

Один процесс для прототипа. Не копируй учебный ConnectionManager как production
многопроцессный сервер. Не добавляй Redis/ORM/ECS без текущей причины.
SQLite: параметризованный SQL, явный commit/rollback, миграция перед изменением схемы.
Embedded-доступ выключен по умолчанию и ограничен loopback; публичных debug writes нет.
