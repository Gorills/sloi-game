# Canvas и интерфейс

## Вход

Прочитай AGENTS.md, docs/design/README.md и документ нужной поверхности.
Проверь DOM, обработчики ввода, presentation state и способ сборки.

## Процедура

1. Определи действие игрока и состояния normal/empty/disabled/pending/error/offline.
2. Используй client/design/tokens.json; не добавляй вторую палитру/случайные отступы.
   Семантические кнопки/диалоги — DOM; мир — Canvas.
3. Отдели ввод от рендерера и транспорта. Обработчик не меняет серверный результат.
4. Пересчитай pointer через bounding rect и viewport; согласуй CSS size и DPR.
   Отрисовка не определяет шаг симуляции; cleanup снимает listeners/animation loop.
5. Проверь keyboard, текстовое поле, Esc/возврат фокуса, blur/hidden, resize,
   200% текста, reduced motion, длинные подписи и недоступное действие.
6. Запусти браузерный сценарий; просмотри кадры. Скриншот не заменяет interaction test.
7. Выполни [визуальную самооценку](../../../docs/design/visual-acceptance.md):
   конкретные наблюдения по кадрам и ассетам, эталон сравнения, собственный вердикт.
   Отсутствие технических дефектов не подтверждает художественное качество.

## Визуальная приёмка

Угроза, цель и доступное действие различимы; декоративный эффект не закрывает сигнал.
Сохранены хитбокс/направление, цвет не единственный носитель смысла.
Не называй narrow screenshot поддержкой телефонов; не добавляй engine abstraction
ради единственной сцены. Оптимизация Canvas — после измерения, не по привычке.

## Результат

Проверенные состояния/размеры/устройства, просмотренные кадры и оставшиеся ограничения.
Источники: [S5/S6/G4/G5]; числа/палитра проекта — проверяемая гипотеза, не стандарт отрасли.
